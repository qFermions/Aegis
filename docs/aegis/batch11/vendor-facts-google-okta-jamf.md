# Vendor facts: the six senior-tech rules in the Google, Okta, Jamf, Mac, Fleet, Slack, GitHub and Linear runbooks (batch 11)

Collected 2026-11-13. Read-only research. No vendor API was called, no credential was used.
Every line: id | fact and where a runbook uses it | URL opened | date | how read | verbatim quote (under 25 words) | CONFIRMED or UNCONFIRMED.
Hosts read: support.google.com, knowledge.workspace.google.com (where support.google.com/a now redirects), www.google.com/appsstatus, help.okta.com, support.okta.com, status.okta.com, docs.github.com, www.githubstatus.com, slack.com/help, slack-status.com, linear.app/docs, linearstatus.com, status.jamf.com, www.apple.com/support/systemstatus.
"fetch tool summary" = the page fetched with the web fetch tool, which returns a model's reading of the page; its quotes are as that tool returned them. Where the tool described a step in its own words, the line says "as the tool described it" and gives no quote for that part.
CONFIRMED = the vendor page was opened and the quote was returned from it. UNCONFIRMED = the page could not be opened or does not say so; nothing in a runbook rests on it as a vendor menu path or a number, and the runbook line carries "[unconfirmed: check the vendor page]" or an org gap marker instead.

The rule names are those of `docs/aegis/answer-format.md`, section 2.
