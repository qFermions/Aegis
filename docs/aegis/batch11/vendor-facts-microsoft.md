# Vendor facts: the senior-tech rules in the Microsoft and vendor-neutral runbooks (batch 11, task 5)

Collected 2026-11-13. Read-only research. No vendor API was called, no credential was used.
Every line: id | fact and where a runbook uses it | URL opened | date | how read | verbatim quote (under 25 words) | CONFIRMED or UNCONFIRMED.
"Microsoft Learn fetch" = the page fetched through the Microsoft Learn tool (full page as markdown).
"Microsoft Learn search excerpt" = an excerpt of that page as the Microsoft Learn search tool returned it.
"fetch tool, page text" = the page fetched with the web fetch tool, which returned the page's own text; "fetch tool summary" = that tool's reading of the page, and its quote is as the tool gave it.
CONFIRMED = the vendor page was opened and the quote is on it. UNCONFIRMED = it could not be opened or does not say so; no runbook writes it as a vendor menu path or a number.

The rules are in `docs/aegis/answer-format.md` section 2. Runbook lines that cite nothing below are steps that name no vendor feature (ask who is affected, test from another network, call a number on file) or point to a gate the runbook already holds.

## A new way in before the old way out (`/mfa-issue`, `/password-reset`, `/device-wipe`)

- MB-01. A Temporary Access Pass is a time-limited passcode, and Microsoft names it for recovery when a user loses a strong method; the reason `/mfa-issue` uses it on the lost-or-replaced-device path. | https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass | 2026-11-13 | Microsoft Learn fetch | "A TAP also makes recovery easier when a user loses or forgets a strong authentication method." | CONFIRMED
- MB-02. The roles that may issue a pass: at least Authentication Administrator for a member, Privileged Authentication Administrator when the user is an admin; named in the PORTAL ACTION of `mfa-temporary-access-pass-portal`. | https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass | 2026-11-13 | Microsoft Learn fetch | "Authentication Administrators can create, delete, and view a TAP for members (except themselves)." and "Privileged Authentication Administrators can create, delete, and view a TAP for admins and members (except themselves)." | CONFIRMED
- MB-03. The path to issue one: Entra admin center, Entra ID, Users, the user, Authentication methods, Add authentication method, Temporary Access Pass, Add. | same URL | 2026-11-13 | Microsoft Learn fetch | "Select Authentication methods and select Add authentication method." | CONFIRMED
- MB-04. The pass value shows once, when it is created. | same URL | 2026-11-13 | Microsoft Learn fetch | "You can't view this value after you select Ok." | CONFIRMED
- MB-05. A pass can be created for any user, but only a user in the Temporary Access Pass policy can sign in with it; the policy is read at Entra ID, Authentication methods, Policies, and changing it takes the Authentication Policy Administrator role. `/mfa-issue` reads it before the gate and does not change it. | same URL | 2026-11-13 | Microsoft Learn fetch | "Although you can create a TAP for any user, only users included in the policy can sign in with it." | CONFIRMED
- MB-06. The policy's default lifetime is 1 hour, the allowed range 10 to 43,200 minutes (30 days), and one-time use is a policy setting (default False); a single pass may set its own lifetime inside the policy's range. | same URL | 2026-11-13 | Microsoft Learn fetch (the settings table) | "Individual passes within the minimum and maximum lifetime configured by the policy can override default value." | CONFIRMED
- MB-07. After signing in with the pass the user registers a method, and Microsoft says the old ones should go afterwards; the order `/mfa-issue` follows. | same URL | 2026-11-13 | Microsoft Learn fetch | "Users who update their authentication methods due to losing their credentials or device should make sure they remove the old authentication methods." | CONFIRMED
- MB-08. With a one-time pass the registration must finish within 10 minutes of the sign-in; said to the user at the handover. | same URL | 2026-11-13 | Microsoft Learn fetch | "the user must complete the registration within 10 minutes of sign-in with the one-time TAP." | CONFIRMED
- MB-09. A user holds one pass at a time, and a new one overrides the old; so an old pass stays listed until then, which is why the read-back is bounded in time. | same URL | 2026-11-13 | Microsoft Learn fetch | "Each user can only have one TAP." | CONFIRMED
- MB-10. A pass is deleted from the user's Authentication methods list; the rollback path of the pass gate (under `mfa-method-delete-portal`). | same URL | 2026-11-13 | Microsoft Learn fetch | "On the right-hand side of the Temporary Access Pass authentication method shown in the list, select Delete." | CONFIRMED
- MB-11. In Microsoft Graph a pass is a temporaryAccessPassAuthenticationMethod with createdDateTime, isUsable and methodUsabilityReason (EnabledByPolicy, DisabledByPolicy, Expired, NotYetValid, OneTimeUsed), and a read never returns its value; what `msgraph-client.js verify-temporary-access-pass` judges. | https://learn.microsoft.com/en-us/graph/api/resources/temporaryaccesspassauthenticationmethod?view=graph-rest-1.0 | 2026-11-13 | Microsoft Learn fetch | "Hidden in subsequent read operations and returned as null with GET." | CONFIRMED
- MB-12. The list of a user's authentication methods needs the application permission UserAuthenticationMethod.Read.All, which the connector already declares, and the Temporary Access Pass is one of the method types Graph v1.0 manages. | https://learn.microsoft.com/en-us/graph/api/authentication-list-methods?view=graph-rest-1.0 and https://learn.microsoft.com/en-us/graph/api/resources/authenticationmethods-overview?view=graph-rest-1.0 | 2026-11-13 | Microsoft Learn fetch (the permissions table: Application, UserAuthenticationMethod.Read.All) | "Retrieve a list of authentication methods registered to a user." | CONFIRMED
- MB-12a. UNCONFIRMED: that the list read (not the pass's own read) returns createdDateTime, isUsable and methodUsabilityReason for a pass entry. The resource page gives the properties and the list page says it returns the derived types, but neither shows a list response holding a pass. Nothing in a runbook rests on it: when createdDateTime is missing or not a time, the read-back answers INCONCLUSIVE, never a pass. To check on a test tenant (`docs/aegis/owner/test-tenant-runbook.md`).
- MB-13. A new pass can take a few minutes to show. | https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass | 2026-11-13 | Microsoft Learn fetch | "It can take a few minutes for changes to replicate." | CONFIRMED
- MB-14. The pass can register Microsoft Authenticator from inside the app. | same URL | 2026-11-13 | Microsoft Learn fetch | "Users can also use their TAP to register Microsoft Authenticator with their account." | CONFIRMED
- MB-15. A lost phone's Authenticator registration stays in Entra until an admin deletes it, so a device wipe alone does not take it away; said in `/device-wipe`. | https://learn.microsoft.com/en-us/graph/api/resources/authenticationmethods-overview?view=graph-rest-1.0 | 2026-11-13 | Microsoft Learn fetch | "You can retrieve details of a user's Microsoft Authenticator registration, and delete it if the user has lost the phone." | CONFIRMED

## Who else, and what left (`/sharepoint-access`, `/mailbox-permissions`, `/shared-mailbox`, `/group-membership-audit`, `/distribution-list`, `/conditional-access`, `/security-alert-triage`, `/offboard`)

- MB-20. The audit log is searched in the Microsoft Purview portal, Audit, by a person who holds the Audit Logs or View-Only Audit Logs role. | https://learn.microsoft.com/purview/audit-search | 2026-11-13 | Microsoft Learn search excerpt | "You must be assigned the Audit Logs or View-Only Audit Logs roles in the Microsoft Purview portal to search the audit log." | CONFIRMED
- MB-21. Without an E5 licence the audit log goes back 180 days, so a path open longer than that cannot be read in full. | same URL | 2026-11-13 | Microsoft Learn search excerpt | "For users assigned any other (non-E5) Office 365 or Microsoft 365 license, the system retains audit records for 180 days." | CONFIRMED
- MB-22. The file and sharing activities to search for, by friendly name and operation: Accessed file (FileAccessed), Downloaded file (FileDownloaded), Shared file, folder, or site (SharingSet), Created sharing invitation (SharingInvitationCreated), Created a company shareable link (CompanyLinkCreated), Created an anonymous link (AnonymousLinkCreated), Used an anonymous link (AnonymousLinkUsed), Added user or group to SharePoint group (AddedToGroup). | https://learn.microsoft.com/en-us/purview/audit-log-activities | 2026-11-13 | fetch tool, page text (read in three parts; the sharing and site-permission rows from the saved text of the third) | "Anyone with this link can access the resource without having to be authenticated." | CONFIRMED
- MB-23. The mailbox activities to search for: Accessed mailbox items (MailItemsAccessed), Sent message using Send As permissions (SendAs), Added delegate mailbox permissions (its operation carries the name of the Exchange cmdlet that grants Full Access; not written out here, because the safety scanner reads that name as a command). | same URL | 2026-11-13 | fetch tool summary (the first part of the page) | "Analyzing audit records for this activity is useful when investigating compromised email account." | CONFIRMED
- MB-23a. For a shared mailbox the address goes in the Keywords field of the search. | https://learn.microsoft.com/purview/audit-log-search-for-mailbox-activities | 2026-11-13 | Microsoft Learn search excerpt | "When searching for shared mailbox activities, enter the SMTP address under the Keywords field, not the Users field." | CONFIRMED
- MB-24. A group membership change shows as Added member to group (AddMemberToGroup). | https://learn.microsoft.com/en-us/purview/audit-log-activities | 2026-11-13 | fetch tool summary (the second part of the page) | "Added member to group" | CONFIRMED
- MB-25. Entra's own audit and sign-in logs are at Entra ID, Monitoring & health, and Reports Reader is the least role that reads them. | https://learn.microsoft.com/entra/identity/monitoring-health/howto-access-activity-logs | 2026-11-13 | Microsoft Learn search excerpt | "Reports Reader is the least privileged role required to access the activity logs." | CONFIRMED
- MB-25a. A message trace is run in the Exchange admin center, Mail flow, Message trace, and shows what the service delivered and to whom. | https://learn.microsoft.com/exchange/monitoring/trace-an-email-message/message-trace-modern-eac | 2026-11-14 | Microsoft Learn search excerpt | "In the EAC at https://admin.exchange.microsoft.com, go to **Mail flow** > **Message trace**." | CONFIRMED

## Mail that fails the sender-authentication checks (`/email-quarantine`, `/email-whitelist`, `/email-to-spam`)

- MB-40. Microsoft's first choice for allowing a sender is the Tenant Allow/Block List; allowed sender or domain lists in an anti-spam policy are the last. | https://learn.microsoft.com/defender-office-365/create-safe-sender-lists-in-office-365 | 2026-11-13 | Microsoft Learn search excerpt | "Our number one recommended option for allowing mail from senders or domains is the Tenant Allow/Block List." | CONFIRMED
- MB-41. An allowed domain in an anti-spam policy skips the sender-authentication checks themselves. | same URL | 2026-11-13 | Microsoft Learn search excerpt | "senders bypass all spam, spoof, phishing protection (except high confidence phishing), and sender authentication (SPF, DKIM, DMARC)." | CONFIRMED
- MB-41a. Microsoft calls allowed sender or domain lists in an anti-spam policy a method for temporary testing only. | https://learn.microsoft.com/defender-office-365/create-safe-sender-lists-in-office-365 | 2026-11-14 | Microsoft Learn search excerpt | "This method is best used for temporary testing only." | CONFIRMED
- MB-42. A mail flow rule keyed on the sender's domain alone is never right. | same URL | 2026-11-13 | Microsoft Learn search excerpt | "Never configure mail flow rules with only the sender domain as the condition to skip spam filtering." | CONFIRMED
- MB-43. The checks' results are in the message's Authentication-results header. | https://learn.microsoft.com/en-us/defender-office-365/message-headers-eop-mdo | 2026-11-13 | fetch tool, page text | "The results of email authentication checks for SPF, DKIM, and DMARC are recorded (stamped) in the Authentication-results message header in inbound messages." | CONFIRMED
- MB-44. What the values mean: spf=fail (the source is not in the domain's SPF record), dkim=none (the message was not signed), dmarc=fail, and a DMARC permerror that only the domain's owner can fix. | same URL | 2026-11-13 | fetch tool, page text | "you might need to contact the domain's owner in order to resolve the issue." | CONFIRMED
- MB-45. The fix is on the sender's side: the sending domain's owner publishes SPF, DKIM and DMARC in its own DNS. | https://learn.microsoft.com/en-us/defender-office-365/email-authentication-about | 2026-11-13 | fetch tool, page text | "Use the configuration information that's provided by your domain registrar or DNS hosting service." | CONFIRMED
- MB-46. While the sender fixes it, Microsoft's own advice is a scoped allow entry, not the whole domain. | same URL | 2026-11-13 | fetch tool, page text | "use a scoped allow entry in the Tenant Allow/Block List or authenticated relay rather than allowing the entire sending domain." | CONFIRMED
- MB-47. An allow entry is made by submitting the blocked message as clean. | https://learn.microsoft.com/defender-office-365/tenant-allow-block-list-email-spoof-configure | 2026-11-13 | Microsoft Learn search excerpt | "an allow entry for the sender is added to the Domains & email addresses tab" | CONFIRMED
- MB-48. An allow entry for a domain or address runs out: 45 days after it was last used by default, and a fixed date can be at most 30 days ahead. | same URL | 2026-11-13 | Microsoft Learn search excerpt | "the entry expires after 45 days from last used date." | CONFIRMED
- MB-49. Microsoft's warning on allow entries. | same URL | 2026-11-13 | Microsoft Learn search excerpt | "Unnecessary allow entries expose your organization to malicious email that the system would otherwise filter" | CONFIRMED
- MB-49a. UNCONFIRMED: how long an allow entry for a spoofed sender (the spoof pair) lasts. The excerpts read give the expiry for domains and addresses only. No runbook states a period for a spoofed-sender entry.

## Offboarding: where the mail goes, what it costs, and the restore window (`/offboard`, `/shared-mailbox`, `/license-audit`)

- MB-50. A user mailbox converted to shared needs no licence while it is under 50 GB. | https://learn.microsoft.com/microsoft-365/admin/email/convert-user-mailbox-to-shared-mailbox?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "If the mailbox is smaller than 50 GB, you can remove the license from the user, and stop paying for it." | CONFIRMED
- MB-51. The licence rules for a shared mailbox: it needs an Exchange Online Plan 2 licence when it holds more than 50 GB, uses in-place archiving or is on litigation hold. | https://learn.microsoft.com/microsoft-365/admin/email/create-a-shared-mailbox?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "The shared mailbox has more than 50 GB of storage in use." | CONFIRMED
- MB-52. The account must stay: a shared mailbox and a forward both hang on it. | https://learn.microsoft.com/microsoft-365/admin/add-users/remove-former-employee-step-7?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "Don't delete the account if you've set up email forwarding or converted it to a shared mailbox." | CONFIRMED
- MB-53. The old sign-in still opens a converted mailbox until the password is reset, which is why `/offboard` contains the identity before it converts. | https://learn.microsoft.com/microsoft-365/admin/email/convert-user-mailbox-to-shared-mailbox?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "the original username and password will continue to work on the shared mailbox" | CONFIRMED
- MB-54. Forwarding is set at Microsoft 365 admin center, Users, Active users, the user, Mail, Manage email forwarding, and it carries only new mail. | https://learn.microsoft.com/en-us/microsoft-365/admin/add-users/remove-former-employee-step-4?view=o365-worldwide | 2026-11-13 | fetch tool, page text | "If you set up email forwarding, only new emails sent to the former employee's email address are sent to the current employee." | CONFIRMED
- MB-54a. A forward set on a person's own mailbox needs that account licensed, and removing the licence stops the forward. | https://learn.microsoft.com/microsoft-365/admin/email/configure-email-forwarding?view=o365-worldwide | 2026-11-14 | Microsoft Learn search excerpt | "Email forwarding requires that the *from* account has a license unless it's a shared mailbox." | CONFIRMED
- MB-55. After a licence is removed the mail is held 30 days, then deleted for good. | https://learn.microsoft.com/microsoft-365/admin/add-users/remove-former-employee-step-6?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "When you remove a license, that user's data is held for 30 days." | CONFIRMED
- MB-56. A deleted account can be restored for about 30 days, and deleting it stops its mail from arriving; a synced account is deleted and restored in the local Active Directory. | https://learn.microsoft.com/microsoft-365/admin/add-users/remove-former-employee-step-7?view=o365-worldwide | 2026-11-13 | Microsoft Learn search excerpt | "When you delete a user, the account becomes inactive for approximately 30 days." | CONFIRMED
- MB-57. Holds come off before a licence does, and a mailbox kept inactive for compliance can be neither forwarded nor converted. | https://learn.microsoft.com/microsoft-365/admin/add-users/remove-former-employee-step-6?view=o365-worldwide and the step-4 page above | 2026-11-13 | Microsoft Learn search excerpt; fetch tool, page text | "Before you remove a license, you must remove all holds for the user." | CONFIRMED
- MB-58. UNCONFIRMED: a price for a licence, and any Microsoft guidance on how long a leaver's forward or shared mailbox should be kept. No page read gives either. `/offboard` states no price (it compares one paid licence a month against none) and leaves the period to the organization under an [org gap] marker.
