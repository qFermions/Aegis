# Vendor facts: the four judgment rules in the existing runbooks (batch 12, task 1)

Collected 2026-11-14. Read-only research. No vendor API was called, no credential was used.
Every line: id | fact and where a runbook uses it | URL opened | date | how read | verbatim quote (under 25 words) | CONFIRMED or UNCONFIRMED.
Hosts read: learn.microsoft.com, support.microsoft.com, support.google.com, knowledge.workspace.google.com (where support.google.com/a now redirects).
"fetch tool summary" = the page fetched with the web fetch tool, which returns a model's reading of the page; its quotes are as that tool returned them. "fetch tool page text" = the tool returned the page's own Markdown, and the quote is copied from it.
CONFIRMED = the vendor page was opened and the quote was returned from it. UNCONFIRMED = the page could not be opened or does not say so; nothing in a runbook rests on it as a vendor menu path or a number, and the runbook line carries "[unconfirmed: check the vendor page]" instead.

The rule letters are those of `docs/aegis/answer-format.md`, section 2, "Five judgment rules (batch 12)": a, escalate on a smell of compromise; b, least privilege by default; c, recover to a safe place first; d, ask first when ambiguous and risky.

- RR-01. Exchange Online accepts a mail-enabled security group as the holder of a mailbox permission, and a mailbox granted Full Access through such a group does not auto-map in the member's Outlook. - RR-02.
