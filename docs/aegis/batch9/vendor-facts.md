Read-only research. No vendor API was called, no PowerShell session was opened, no credential was used.
Every line: fact | URL opened | date | how read | verbatim quote (under 25 words).
"vendor docs page" = the whole page fetched from learn.microsoft.com with the Microsoft Learn fetch tool.
"search excerpt" = only the excerpts the Microsoft Learn search tool returned for that page were read, not the whole page.

### Sign-in: app-only with a certificate

- X-01. App-only (certificate based) authentication uses a Microsoft Entra app and a certificate for unattended scripts; module version 2.0.4 or later for Connect-ExchangeOnline. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "Certificate based authentication (CBA) or app-only authentication as described in this article supports unattended script and automation scenarios"
- X-02. Connect-ExchangeOnline takes a certificate file with a SecureString password, or a thumbprint, with -AppId and -Organization. | https://learn.microsoft.com/powershell/module/exchangepowershell/connect-exchangeonline | 2026-11-06 | search excerpt | "[-CertificateFilePath <String>] [-CertificatePassword <SecureString>] [-CertificateThumbprint <String>]"
- X-03. The thumbprint form works only on Windows, with the certificate in the user store; so on macOS and Linux the connector uses EXO_CERTIFICATE_PATH. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "The CertificateThumbprint parameter is supported only in Microsoft Windows."
- X-04. The Organization value is the primary .onmicrosoft.com domain; the connector refuses any other form of EXO_ORGANIZATION. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "use the primary `.onmicrosoft.com` domain for your organization as the value of the *Organization* parameter."
- X-05. The API permission is the application permission Office 365 Exchange Online > Exchange.ManageAsApp, with tenant-wide admin consent. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "Grant tenant-wide admin consent for each permission."
- X-06. Global Reader is a supported Microsoft Entra role for app-only Exchange Online PowerShell; the session's RBAC comes from the role in the token. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "The session's role based access control (RBAC) is configured using the directory role information that's available in the token."
- X-07. Connect-ExchangeOnline has a -CommandName parameter (a string array); the connector passes the four read cmdlets. UNCONFIRMED: that it limits the session to those commands; only the syntax line was read, not its description. | https://learn.microsoft.com/powershell/module/exchangepowershell/connect-exchangeonline | 2026-11-06 | search excerpt | "[[-CommandName] <String[]>]"
- X-24. The public certificate (.cer) is uploaded under the app's Certificates & secrets. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "browse to the public certificate (`.cer` file) you exported in Step 3, and then select **Add**."
- X-25. CNG certificates are not supported; the certificate must come from a CSP key provider. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "Cryptography: Next Generation (CNG) certificates aren't supported for app-only authentication with Exchange."
- X-26. Microsoft warns that a certificate file's password stored for automation weakens the method; the owner doc says to prefer the thumbprint on Windows and to keep the password in a secret manager. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "there's really no automated *and* secure way to connect using a local certificate."
- X-27. The default delegated Microsoft Graph User.Read consent is revoked after Exchange.ManageAsApp is granted. | https://learn.microsoft.com/powershell/exchange/app-only-auth-powershell-v2 | 2026-11-06 | vendor docs page | "For the default **Microsoft Graph** &gt; **User.Read** entry, select **...** &gt; **Revoke admin consent**"

### The reads and the fields parsed

- X-08. Get-QuarantineMessage is cloud only and views quarantined messages. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-quarantinemessage | 2026-11-06 | vendor docs page | "Use the Get-QuarantineMessage cmdlet to view quarantined messages and files in your cloud-based organization."
- X-09. ReleaseStatus has seven values: Approved, Denied, Error, NotReleased, PreparingToRelease, Released, Requested. UNCONFIRMED: the page lists them for the -ReleaseStatus filter, not for the output property, and does not show the output's case (RELEASED); the connector compares in upper case and makes any other value INCONCLUSIVE. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-quarantinemessage | 2026-11-06 | vendor docs page | "The ReleaseStatus parameter filters the results by the release status of the message."
- X-10. A quarantine Identity is GUID1\GUID2, and a non-existent Identity returns every object; so the read-back counts the records that carry the asked Identity and needs exactly one. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-quarantinemessage | 2026-11-06 | vendor docs page | "The value $null or a non-existent value for the Identity parameter returns *all* objects"
- X-11. -MessageId filters on the Message-ID header, angle brackets included; -RecipientAddress filters on the recipient's address. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-quarantinemessage | 2026-11-06 | vendor docs page | "The MessageId parameter filters the results by the Message-ID header field of the message."
- X-12. A summary read without dates covers the last 16 days, so a message older than that is absent from a --message-id read (INCONCLUSIVE, never a fail). | https://learn.microsoft.com/powershell/module/exchangepowershell/get-quarantinemessage | 2026-11-06 | vendor docs page | "By default, if you don't use the StartReceivedDate and EndReceivedDate parameters, the command returns data for the last 16 days."
- X-13. Get-RecipientPermission shows Send As only, and its -Trustee filter can miss a principal with several Sids; so the connector reads the mailbox's whole list and matches the trustee itself. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-recipientpermission | 2026-11-06 | vendor docs page | "This cmdlet doesn't return expected results when the recipient specified by the Trustee parameter has multiple `SecurityPrincipalIdParameter` (Sid) values."
- X-14. Get-RecipientPermission's Identity has the same caution: a non-existent value returns every object; so an answer covering more than one mailbox is INCONCLUSIVE. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-recipientpermission | 2026-11-06 | vendor docs page | "The value $null or a non-existent value for the Identity parameter returns *all* objects"
- X-15. UNCONFIRMED: the output field names of Get-RecipientPermission (Trustee, AccessControlType, AccessRights, IsInherited). The page lists no output properties; the names come from the parameters and from the Send As verify step. A missing field makes the read-back INCONCLUSIVE. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-recipientpermission | 2026-11-06 | vendor docs page | "Use the Get-RecipientPermission cmdlet to view information about SendAs permissions that are configured for users in a cloud-based organization."
- X-16. Get-MailboxPermission prints Identity, User, AccessRights (FullAccess among them), IsInherited and Deny; Deny true means denied and usually overrides allow. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-mailboxpermission | 2026-11-06 | search excerpt | "Deny: Whether the permission is allowed (False) or denied (True). Typically, deny permissions override allow permissions."
- X-17. By default FullAccess is directly assigned to NT AUTHORITY\SELF, so that entry is never read as a delegate. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-mailboxpermission | 2026-11-06 | search excerpt | "FullAccess and ReadPermission are directly assigned to NT AUTHORITY\SELF. This entry gives a user permission to their own mailbox."
- X-18. Microsoft's own check for Full Access reads User, Deny, IsInherited and AccessRights from Get-MailboxPermission. | https://learn.microsoft.com/exchange/recipients-in-exchange-online/manage-permissions-for-recipients | 2026-11-06 | vendor docs page | "Get-MailboxPermission <MailboxIdentity> \| where {$_.AccessRights -like 'Full*'} \| Format-Table User,Deny,IsInherited,AccessRights -Auto"
- X-19. Send on behalf is read from the mailbox's GrantSendOnBehalfTo field. | https://learn.microsoft.com/exchange/recipients-in-exchange-online/manage-permissions-for-recipients | 2026-11-06 | vendor docs page | "Get-Mailbox -Identity <MailboxIdentity> \| Format-List GrantSendOnBehalfTo"
- X-20. Get-Mailbox views mailbox objects; Microsoft recommends Get-EXOMailbox in Exchange Online. The connector keeps Get-Mailbox, the cmdlet the task names and the manage-permissions page uses. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-mailbox | 2026-11-06 | search excerpt | "Use the Get-Mailbox cmdlet to view mailbox objects and attributes, populate property pages, or supply mailbox information to other tasks."
- X-21. Full Access, Send As and Send on behalf are the three delegate permissions; Send As wins when a delegate has both. | https://learn.microsoft.com/exchange/recipients-in-exchange-online/manage-permissions-for-recipients | 2026-11-06 | vendor docs page | "If a user has both **Send as** and **Send on behalf** permissions to a mailbox or group, the **Send as** permission is always used."
- X-22. UNCONFIRMED: whether Exchange Online prints a delegate in User or Trustee as the address or as a display name (Get-MailboxPermission has an -IncludeUserWithDisplayNames switch). So a direct grant to a principal not shown as an address makes the read-back INCONCLUSIVE, never a pass. | https://learn.microsoft.com/powershell/module/exchangepowershell/get-mailboxpermission | 2026-11-06 | search excerpt | "-IncludeUserWithDisplayNames"
