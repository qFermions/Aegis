# Aegis boundary audit: every path that could change a production system

Product boundary (`PRODUCT_CONTRACT.md`, batch 1 charter): AEGIS ADVISES; HUMANS EXECUTE PRODUCTION CHANGES. A code path that can make a production account change, a device action, a tenant mutation, a ticket post or close, a scheduled run, a sent message or a payment without a human-executed step is a project failure.

Audited on 2026-10-27 at base `d5fc8c0`; fixes on branch `chore/baseline-and-boundary`. Method: every tracked JavaScript file outside tests was searched for network, process, scheduling, mail and payment calls (`docs/aegis/evidence/boundary-grep-io.txt`) and for write HTTP methods (`docs/aegis/evidence/boundary-grep-write-verbs.txt`); every agent card and plugin was read for its tool registry (`docs/aegis/evidence/boundary-agent-tools.txt`); every command and module document is covered by the state-change inventory the safety-gate suite checks (`docs/security/STATE_CHANGE_INVENTORY.json`, `docs/aegis/evidence/boundary-safety-gate-tests.txt`). Each row below was then opened at the cited line.

Verdicts: **fixed** (it was a violation; the commit and test are named), **human-executed** (a human step is required and the code cannot take it), **local only** (it writes nothing outside this machine's files), **read-only**, **none exists**, **residual** (no code gate; left with the reason, and named in the batch report).

## Result

- One violation (rows 1 and 2), fixed in its own commit with tests.
- Rows with no code gate left: rows 4 and 5 (agents with a shell) and row 12 (the checklist command runner). Each is named in the batch report with the reason it was left: rows 4 and 5 need a change to the agents' tools or a hook in `.claude/settings.json`, both owner decisions; row 12 has no production target and adds no reach beyond the operator's own shell.
- Tier check (addendum to task 2): every path above that could mutate a production system (rows 1 to 5 and 12) is in the C list of `.github/risk-tiers.json`, with one stated exception: `scripts/jira-client.js`, `.claude/**` (the 77 commands of row 3, rows 2, 4 and 5), `modules/security/**`, and `modules/automation/scripts/deploy-check.js` (added in `0a4fc3c`, test in `scripts/risk_tier.test.js`). `scripts/init-memory.js` was added too (`62eff38`). Exception: the procedure modules of row 3 outside `modules/security/` (for example `modules/it_support/`) match `modules/**`, tier B. They are text an administrator runs, and no Aegis code executes them; the commands that carry the same procedures to the operator are under `.claude/**`, tier C. Evidence: `docs/aegis/evidence/boundary-risk-tier-tests.txt`.
