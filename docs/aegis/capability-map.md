# Aegis capability map (evidence and drift)

This file maps what the Aegis repository can actually do against five capabilities (IT support and infrastructure troubleshooting; defensive cybersecurity and incident response guidance; platform engineering and infrastructure development; agent strategy and workflow design; agent development, testing and operation), one row per capability and platform, each with a status and the evidence behind it. Microsoft and Google always have separate rows. Okta, Jamf and macOS ship in the Google lane (v8.9) and are tested by its corpus, so they share a Google row where one check covers them all and the Platform column names each one (rows 17, 31 and 36; row 12 names Okta only since batch G2, whose Google half is row 59); rows marked platform-neutral hold capabilities that have no platform. It maps commit `d266f6b` (branch `chore/baseline-and-boundary`, base `main` at `d5fc8c0`; `d266f6b` adds only the Phase 0 baseline captures and review notes on top of `d5fc8c0`), and was written on 2026-10-27. Status is one of `verified now` (a deterministic check run in this session proves the stated claim), `implemented but unverified` (the code or content exists, nothing in this session or in the tree checks it), `partial` (part of the claim is checked, part is not, or part is not built) and `missing` (nothing in the repo implements it). "Verified now" rows cite only output produced on 2026-10-27: the Phase 0 captures in `docs/baseline/` (fresh clone of `d5fc8c0`, node v24.22.1, pwsh 7.5.4) or the captures in `docs/aegis/evidence/` (same runtimes; each file opens with its command line, and the commit and UTC time it ran at are on its header or footer lines: `d266f6b` for this map's own captures, `62eff38` for `boundary-*`, `dfc9da3` for `a4-*`, and `1634a6c` for `untrusted-*`, the worktree commit where the untrusted-data suites and their fixes were built, identical in `scripts/untrusted`, `scripts/graph`, `scripts/memory`, `scripts/replay` and `scripts/tier` to `3446f26` on this branch; the acceptance captures `a1-`, `a3-`, `a5b-`, `a10-`, `a11-` and `final-head-checks.txt` name their commit on their first lines; where a capture was edited after the run, for example to replace a long dash or strip colour codes, its last line says so and line numbers are unchanged). No model-judged run happened in this session, so no row about answer quality is `verified now`. Nothing here called a real tenant, ticket system, device, mailbox or scheduler.


Batch 12 (2026-11-14 to 2026-11-18, branch `feat/batch12-expert-lanes`) adds rows 84 to 136 for the four expert lanes (security and incident response, networking, infrastructure and cloud, software engineering) and its own tooling, and a sixth capability, 6. Software engineering; it changes rows 12, 18 and 19. Its statuses use the same words: `verified now` only where a check run in batch 12 proves the claim (captures in `docs/aegis/demo/evidence/batch12/` and `docs/aegis/batch12/lanes/`), and every row about answer content stays `implemented but unverified` or `partial` until a model-judged run on cases its builders did not write measures it.
