## Fix
**What's wrong:** Okta Verify on [FIRST_NAME]'s Mac keeps sending them back to sign in since the macOS update, and reinstalling it didn't help.
**Do this:**
1. Okta Admin Console → Reports → System Log → search [UPN]. Look at the Okta Verify sign-ins since the update. Repeated failures with the same reason point to old sign-in data left on the Mac. Prompts or locations the user doesn't recognize mean you should stop.
2. Ask them to quit Okta Verify fully, reopen it and sign in once. If it still loops, restart the Mac and try once more.
3. Write the macOS version (from Fleet → Hosts → [DEVICE_NAME]) and the Okta Verify version in the ticket.
4. If it still loops: Directory → People → [UPN] → More Actions → Clear User Sessions. Then the user signs in again.
5. Last resort: Reset Authenticators and tick only Okta Verify.
**Done when:** the user finishes one full sign-in without looping.
**Stop if:** the System Log shows activity the user didn't do. Then handle it as a security report.

**Tell the user when done:** Your sign-in works again. If Okta Verify loops again, reply to this ticket.

## Details
- **Runbook:** `/okta-mfa-reset`, section "Okta Verify sign-in loop after a macOS update". The fix was confirmed by the owner, not taken from Okta's published pages.
- **Why the steps are in this order:** the macOS update is the change, so leftover sign-in data on the Mac is the first suspect. They already reinstalled, so reinstalling again won't help. Clearing sessions is a light fix with nothing to undo: the user just signs in again. Resetting authenticators can't be undone, so it comes last.
- **Before step 5 (customer D):**
  - Confirm it's really them on a video call, and have their manager confirm in the IT channel.
  - The head of engineering approves.
  - The account must show **Active**.
  - Tick only Okta Verify. Resetting all authenticators is a separate gate, and nothing here calls for it.
- **Before step 4:** write the current UTC time in the ticket as the start time for the check.
- **Gotcha:** More Actions only shows for active users, and not when an admin opens their own profile.
- **⚠️ Risk:** a reset can't be undone. Until the user enrolls again, the identity check is the only safeguard on the account.
