**Verdict:** This is a planned, friendly offboarding. Nothing points to a compromise. The replay lookup returned MISS. The plan follows `/gws-offboard` (Okta and Google), `/github-offboard-member`, `/linear-workspace-admin` Phase D, `/slack-user-lifecycle` Phase D and `/fleet-device-actions`.

**Approvals and checks before Friday**
- **Written approvals:** The profile asks for written confirmation from HR. "Confirmed w HR" in a comment isn't that. Get HR's note and the head of engineering's approval into the ticket.
- **GitHub login:** The ticket says "i think", so the login is a guess. Confirm it with the manager, and match it to the member list in Phase A. Don't remove anyone based on a guessed login.
- **Independent review:** This plan deletes access in several systems. An out-of-session review must sign it off before step 3.
- **Pre-state:** Save the GitHub role, teams, repositories and forks to `tasks/checkpoints/`.
- **Stop conditions:**
  - They are a Google super admin. That role can sign in to the Admin console without going through Okta, so remove it first.
  - They are one of 2 or fewer GitHub owners, or the only admin of a repository. Hand that role to someone else first.
  - A fork holds work nobody else has. The repository owner decides what happens to it before removal.
- **SCIM in Linear and Slack:** If SCIM is on, Okta's deactivation suspends those accounts. In that case skip the Linear and Slack changes. Aegis only reads them back.
- **Integration settings:** The deactivation options on Okta's Google Workspace integration aren't known yet. Read them before step 3.

**Mail, cost and how long you can undo each step**
- **Mail:** Once the Google account is suspended, it receives no new mail. The manager and HR decide whether mail is redirected, to whom, and until what date. A redirect has no gate in this runbook. If they want one, raise it as its own change before Friday. Proof it works: a test message arrives in the receiving person's inbox.
- **Google cost:** A suspended account is still billed at the full rate. The other options are an Archived User licence (its own change) or deleting the account after the data is moved. A deleted account can be restored for 20 days, then it is gone. Leave the account suspended until the retention decision is in the ticket.
- **GitHub:** The paid seat count doesn't go down by itself; the plan owner lowers it. A removed member can be reinstated within 3 months.
- **Linear:** A suspended member drops off the next billing cycle. Unsuspending reverses it, and nothing is deleted.
- **Slack:** A deactivated account can be reactivated, but channel memberships have to be rebuilt by hand.

**Risks**

- **Secrets:** If they could read repository secrets, deploy keys or tokens, rotate those at the issuer. Removing the person doesn't make a copied secret useless.
