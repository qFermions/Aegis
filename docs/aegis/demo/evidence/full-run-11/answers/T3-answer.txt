## Incident answer
**Severity:** SEV-3. We suspect a compromise but see no sign of use yet. At risk: the client files on the Mac and any Google or Slack sessions still signed in on it.

**Contain first:**
1. Read the Mac's record (no change): Jamf Pro → Computers → Search inventory → `[SERIAL_NUMBER]`. Note its last check-in, macOS, chip, whether FileVault is on, whether a bootstrap token is stored, and any commands still pending. FileVault decides how exposed the files are.
2. **Lock the Mac.** Decided by the studio manager. First store a six-digit PIN in the password manager. Then: Management → **Lock Computer**, with a return message. This deletes nothing, and the PIN undoes it. It runs only when the Mac next connects.
3. **Sign the designer out of Google everywhere.** Decided by the studio manager. Admin console → Directory → Users → `[USER@DOMAIN.COM]` → Security → Sign-in cookies → **Reset**. Nothing is lost, and the designer just signs in again on their other devices.
4. **Slack:** the runbook has no way to sign out one person, and the workspace-wide reset is a mass action. The security lead decides whether it is needed.
5. **Wipe later, not now:** only if the security lead calls for it. It needs both the studio manager and the designer's own manager to approve, plus an independent review.

**Preserve:** before you lock, keep a copy of the Jamf record and its Management History, the designer's Google sign-in and Drive audit events since last night, Slack access logs if your plan has them, and the police report number.

**Escalate to:** the security lead or security on-call. They need the serial, the designer, when it was taken, the last check-in, the FileVault state, and the designer's sign-ins since last night. Nobody calls this harmless until they have looked.

**Communications:** confirm the request first by calling the studio manager back on the number in the staff list. If the client contracts require it, the studio manager decides whether to tell clients. Tell the designer: IT is securing their accounts, they should expect to be asked to sign in again, and they should not try to track the Mac or confront anyone.

**Timeline:** stolen last night (exact time unknown). Reported today. Last check-in unknown until step 1. No sign of use so far.
