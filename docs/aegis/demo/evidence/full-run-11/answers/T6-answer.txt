**Contain first (who decides: the head of engineering; a security report is handled at any hour)**
1. Read Okta Admin Console → Reports → System Log → [UPN]. Check whether the sign-in succeeded, which factor was used, the IP, the time, and any new factor enrolled (R0).
2. If it succeeded or the result is unclear: **suspend** [UPN] (R2, can be undone). Suspending ends every Okta session. It does not end sessions already open inside Google, GitHub, Slack or Linear, so record those for the security lead.
3. Check whether [UPN] holds a Google super admin role. Super admins can sign in to Google directly without going through Okta, so the suspend would not lock them out of Google.
4. Nothing gets deactivated or deleted. Evidence comes first.

**Evidence to keep**

- The original Okta alert, including the Comment 1 text exactly as it came.
- The Google login audit and the GitHub audit log for [UPN].

**Escalate to the security lead / on-call with:** who was affected, what was seen and when, the source IP and country, which apps the user holds, and the System Log export.

- Then reset the password, with "Sign out user" ticked. Give the temporary password over the video call, never in the ticket.
- Remove any Okta Verify factor the user doesn't recognise (separate ticket, `/okta-mfa-reset`).
- Unsuspend last.
