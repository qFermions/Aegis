## Details

**Verdict:** This is the "got a new phone" case in the MFA runbook. No lessons on file apply, and the replay lookup was a miss.

**Before any change**
- **Identity check:** this office has no written rule yet, so the profile's interim one applies: the office manager vouches by phone. Use a number you already have, not one from the ticket. Attackers often ask for MFA resets.
- **Approval:** both changes are permanent, so the profile needs the office manager **and** the practice owner. Patients arriving at nine doesn't skip this step.
- **Timing:** today is a Thursday and the work falls in business hours (08:00–17:00), so the office manager should be reachable.

**Why these two changes**
- **Revoke sessions:** ends any session that was still signed in on the old phone. It's cheap protection in case the phone wasn't really wiped.
- **Delete one method:** removes only the old Authenticator entry. The other option, "Require re-register MFA", clears every phone and app method. On a ticket you do one or the other, never both. Here the one-method delete is enough.

**⚠️ Risks**
- Neither change can be undone. If something goes wrong, the user registers again at aka.ms/mfasetup. Write that recovery path in the ticket before the delete.
- **Don't add a text-message fallback.** The profile says Authenticator only, and adding a phone number would be a separate change.
- **If a Conditional Access policy blocks setup**, stop. Any exclusion is a separate, time-boxed policy change in its own runbook. It is not part of this fix.
