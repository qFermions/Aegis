## Details

**Verdict:** Your mail system is probably fine. One vendor's mail stopping while other mail flows normally usually means one of three things: Defender is holding it, Outlook is sorting it away, or it is never leaving the vendor. The message trace shows which one.

**What each trace result means**
- **Delivered:** the message reached the mailbox. Look in Junk. Then check inbox rules (Outlook on the web → Settings → Mail → Rules) for a rule that moves, deletes or forwards invoice mail. A rule nobody remembers creating that forwards invoices is a sign the account may be compromised. Stop and treat it as a security incident.
- **Quarantined / FilteredAsSpam:** Defender is holding the mail. Open the trace's events tab to see which policy caught it.
- **No record at all:** the messages never arrived. Ask the vendor for their bounce messages. The problem is on their side and no change is needed here.

**Risk warning**
- ⚠️ Fake invoices are a common way to steal money from a business. Before you release anything, read the authentication results. If a message fails SPF/DKIM/DMARC, or comes from a lookalike domain, do not release it.
- You can't take a release back once the message is delivered. Release each message to its one recipient only, never to all recipients.
- Leave "Report as no threats found" unchecked. Sending a report to Microsoft is a separate decision.
- If this keeps happening, adding the vendor to the allow list is a separate mail-filtering change. It needs its own review, plus sign-off from the IT lead and the operations manager.

**Approval:** the IT lead approves each release (Customer C profile).

**Verification checklist**

- [ ] Reason and authentication reviewed for each held item
