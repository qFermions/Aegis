## Details

**Verdict:** This is a standard new-phone case. The runbook is `/mfa-issue` → "New phone / re-register". The replay lookup found no match, and there are no matching lessons.

**What to check first (read-only)**
- **Sign-in logs:** the failure reason sorts the cause. "MFA required, not completed" means the lost phone. A Conditional Access block or a disabled account means another cause, so stop and re-triage.
- **Authentication methods:** write down the old Authenticator entry's type and ID. If more than one entry is listed, delete only the one tied to the old phone.
- **Identity:** the customer has no identity-check rule yet (an org gap). Until it sets one, the office manager vouches by phone. Call the office manager on a number already on file, not one from the ticket. Get approval from both the office manager and the practice owner: neither change can be undone.

**Why these steps**
- **Lighter fixes first:** none applies. Asking the user to sign in again fails without the second step, and this customer has no text-message fallback. Adding a phone method is not advised, because the profile allows Authenticator only.
- **Revoke sessions:** this cuts off any token still on the old phone. The user says it was wiped, but nobody has confirmed that. Microsoft notes tokens can take a few minutes more to end.
- **Delete one method, not "Require re-register MFA":** it is the narrower change. The runbook allows one or the other on a ticket, never both.
- **Temporary Access Pass:** no runbook here covers it. It is not advised on this ticket.

**If registration is blocked:** that is the runbook's Conditional Access gotcha. Excluding the user from a policy is a separate high-risk change that needs its own `/conditional-access` plan. It is not advised here.

**Old phone:** if Intune still lists it, retiring it is a separate `/device-wipe` ticket and is not advised here.

**Risk warning:** ⚠️ Both changes are permanent. The deleted method cannot be restored; the user can only register a new one. Never turn off MFA for the office as a fix.

**No time promise:** the ticket mentions patients arriving at nine, but the card promises no time. The fix depends on the office manager's callback and the approvals.
