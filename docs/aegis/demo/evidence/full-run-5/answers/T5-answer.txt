Message trace comes first: it shows where the vendor's mail is going before any change is made.

## Fix
**What's wrong:** Mail from one freight vendor no longer reaches accounts payable. Nobody knows yet whether it's being blocked, moved or never arriving. No runbook covers this exact symptom, so these steps are reasoning, not a known fix.
**Do this:**
1. Exchange admin center → Mail flow → Message trace: vendor sender → [USER@DOMAIN.COM], last 10 days. **Delivered** → step 2. **Quarantined** → step 3. **Failed** or no result → step 4.
2. In that mailbox, check Junk, then Inbox rules and forwarding. A rule nobody recognises that moves or forwards invoices: **stop** (security incident).
3. Defender → Quarantine → filter by sender and read the reason. Spam or bulk → step 5. Phish or malware → **stop**.
4. Ask the vendor for the bounce message. Their mail isn't reaching us.
5. Last resort, can't be recalled: release each reviewed invoice to [USER@DOMAIN.COM] only.

**Done when:** the held invoice is in the clerk's inbox. Aegis then checks the quarantine shows it as released.
**Stop if:** the reason is phish, or a mailbox rule was never set up by the user.
**Tell the user now:** IT is tracing where this vendor's emails are going. Please don't act on any payment-detail change from this vendor until IT gets back to you.
**Tell the user when done:** The held invoices are now in your inbox. Tell us if a new one goes missing.

Full reasoning and the ticket note: see Details.

## Details
**Verdict:** One sender's mail missing while other vendors still arrive is usually filtering (Junk or quarantine). In an accounts payable mailbox, a hidden inbox rule or forwarding is a known invoice-fraud pattern, so step 2 checks for one before anything is released.

**Before acting (Customer C):**
- The profile has no way to verify identity ([org gap]). Before any release, the IT lead confirms the requester is the real accounts payable clerk.
- The IT lead approves the release.
- An allow-list entry or mail-flow rule for this vendor would also need the operations manager. It is **not** advised here. If the problem keeps coming back, raise it as a separate change (`/email-whitelist` Method 1, a time-limited sender entry).

**Reading the trace:**
- Delivered with JunkFolder → filtered to Junk. Moving it back is an undoable lighter fix.
- Delivered to the inbox but not visible → suspect a mailbox rule or forwarding (step 2).
- Quarantined → step 3.
- No record → the vendor's mail never reached the tenant (vendor side).

**Phish verdict on a vendor invoice:** the vendor's own account may be compromised. Don't release it. Keep the evidence and send it to `/security-alert-triage`.

**⚠️ Risk:**
- Once released, an invoice can't be recalled.
- Release to the one recipient only, never to all recipients.
- Leave "Report as no threats found" unticked. That sends message evidence to Microsoft and needs its own decision.

**Verification checklist**
- [ ] Trace result recorded (status + date range)
- [ ] Junk folder and inbox rules/forwarding checked; anything suspicious escalated
- [ ] Quarantine reason read; release only if spam or bulk
- [ ] Requester verified and IT lead approval recorded
- [ ] Aegis read-back shows Released; clerk confirms the invoice arrived
