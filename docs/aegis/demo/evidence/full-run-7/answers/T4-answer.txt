## Details

**Verdict:** This is a routine delegation request. Runbook: `/shared-mailbox`, which has one gate for Full Access and one for Send As. The ticket asks for both, so both run now. Neither one is a fallback for the other.

**Customer E context (from the profile):**
- Accounts are cloud-only, so there's no directory sync to wait for.
- Check identity by calling back on the number in the staff list, never a number given in the ticket.
- The managing partner approves changes. Without that approval, stop.

**Risk:** Both gates are R2.
- Full Access opens a whole mailbox to another person. What they read while they had access can't be taken back.
- Mail sent "as" the mailbox can't be recalled.
- Step 2 records the before-state. Each grant needs an approved change record before its double-check runs.

**Rollback:** Undo with `/mailbox-permissions`:
- Full Access: gate `mailbox-permission-remove-portal`
- Send As: gate `mailbox-send-as-remove-portal`

**Notes:**
- Auto-mapping can take a while to show the mailbox in Outlook. If it never shows after a restart, re-add the mailbox to the Outlook profile.
- Send As is not Send on Behalf. With Send As, the sender line shows only the mailbox. Send on Behalf wasn't requested, and it has no gate here.
