## Fix
**What's wrong:** Someone may have signed in to [UPN]'s Okta account from a country nobody on the team is in.
**Do this:**
1. Open Okta Admin Console → Reports → System Log and search for [UPN] over the last 24 hours. Find the foreign sign-in and read its outcome. If it shows FAILURE or DENY, the password was tried but the sign-in was stopped. If it shows SUCCESS, someone else got in, so note which apps they opened afterwards.
2. In the same log, check whether a new sign-in method was added after that sign-in.
3. Go to Directory → People → [UPN] → More Actions → Clear User Sessions. Tick "Also include logout enabled apps and Okta API tokens", then click **Clear and revoke**.
4. Last resort, only if step 1 shows SUCCESS: confirm the person on a video call, then reset their password.

**Done when:** [UPN] has to sign in again everywhere. Aegis then checks that the System Log shows the session clear.
**Stop if:** the log shows admin actions or other accounts touched. Then this is a company-wide incident: escalate to the head of engineering.
**Tell the user now:** Thanks for reporting this so quickly. IT is checking your account's sign-in records. Don't approve any sign-in prompt you didn't start yourself.
**Tell the user when done:** Your account is signed out everywhere. Please sign in again and tell IT if anything looks wrong.

This is a security report across several apps: see Details.
