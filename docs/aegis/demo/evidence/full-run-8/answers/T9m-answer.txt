## Fix
**What's wrong:** Since the macOS update, Okta Verify on [FIRST_NAME]'s Mac keeps sending them back to sign in, and a reinstall did not fix it. The likely cause is a stale session left over from the update.
**Do this:**
1. Open Okta Admin Console → Reports → System Log and search for [UPN]. Repeated unfinished Okta Verify checks from the Mac point to a stale session. Sign-ins or pushes the user did not make mean you should stop.
2. Ask [FIRST_NAME] to quit Okta Verify fully, not just close its window, then reopen it and sign in once.
3. If it still loops, have them restart the Mac and sign in once. Write down the macOS version (shown in Fleet → Hosts → [DEVICE_NAME]) and the Okta Verify version.
4. If it still loops, go to Directory → People → [UPN] → More Actions → Clear User Sessions.
5. Last resort: reset Okta Verify for [UPN] and have them set it up again.

**Done when:** [FIRST_NAME] finishes one full sign-in on the Mac. Aegis then checks that the System Log shows the sessions were cleared.
**Stop if:** the log shows activity [FIRST_NAME] did not make. Then this is a security report, handled at any hour.
**Tell the user now:** IT is looking into the sign-in loop. Please quit Okta Verify completely, open it again and try to sign in once, then tell us what happens.
**Tell the user when done:** You can sign in normally again. If the loop comes back, reply on this ticket.

See Details for the order of steps, the reset's conditions and the ticket note.
