Found the runbook (`/email-quarantine`) and the answer-format rules; writing up the ticket now.

## Fix
**What's wrong:** Mail from one freight vendor has stopped reaching accounts payable since last week. Mail from other vendors still arrives, so the cause is probably a filter or rule that acts on this one sender. That is not confirmed yet.
**Do this:**
1. Run a message trace in Exchange admin center for the vendor's address to the accounts payable address, last 10 days. Delivered means look at mailbox rules. Quarantined means go to step 2. Redirected or Dropped means a mail flow rule. No record means the mail never reached us.
2. In Defender, go to Quarantine, open an invoice and read the reason and the SPF/DKIM/DMARC results.
3. If the reason is spam or bulk and all three pass, release each invoice to the accounts payable address only.
**Done when:** the released invoices are in the inbox and a new one arrives.
**Stop if:** the reason is phish or malware, or the sender authentication checks fail.
**Tell the user now:** IT is tracing where this vendor's invoices went.
**Tell the user when done:** The held invoices are in your inbox now, and new ones arrive normally.

See Details for the reasoning, the other branches and the ticket note.

## Details
**Branches after the step 1 trace:**
- **Delivered:** open the accounts payable mailbox's Inbox rules and Junk folder. Inbox rules are something the user owns. Look at them with the user, and nothing changes at tenant level.
- **Redirected or Dropped by a mail flow rule:** this is a change to mail flow. The profile says it needs the IT lead and the operations manager to approve. It is not part of this round.
- **Failed SPF, DKIM or DMARC:** the vendor fixes the record that failed, in their own DNS. Tell them which result failed, for example "your SPF record does not list the server that sends your invoices". Do not allow their whole domain.
- **No trace record:** the mail never reached us. Ask the vendor for the bounce message they got.

**Changes (one per held message):**
- Step 3 (release one invoice to accounts payable): R2. Double-check: Aegis reads that the message to that recipient shows as Released.
- Only if more invoices keep landing in quarantine after the release and the authentication checks pass: gate `quarantine-allow-entry`, for the one sender address with an expiry, through `/email-whitelist`. The IT lead approves it.

**Risk:** a release cannot be recalled. Release to the one recipient only, never to everyone. Do not tick "Report as no threats found" with the release: sending the report to Microsoft is a separate decision.
**Org gap:** the profile has no method for verifying identity. Before release, the IT lead confirms the request came from accounts payable.
**Approval:** the IT lead.

**Verify:**
- [ ] Trace result recorded
- [ ] Quarantine reason and authentication results reviewed
- [ ] Each invoice released to accounts payable and the read-back shows Released
- [ ] A new invoice arrives
