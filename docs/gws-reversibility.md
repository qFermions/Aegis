# Reversibility — Google Workspace, Okta, Jamf Pro (and the Apple / ChromeOS edges)

One row per administrative action the Google/Okta/Jamf runbooks use. Each row
gives the R-class with the doctrine reason (`CLAUDE.md` R0–R3 table,
`modules/security/security-doctrine.md` SR-2), the undo, the window or limit,
and the official vendor page the claim was checked against, with the check date.
Nothing here is from memory: where a vendor page is silent, the row says so
(`no documented undo`), and where a page could not be opened it would say
`[unverified: fetch blocked]` — no row in this revision needed that marker.

How to read the R-class column: **R0** read · **R1** one object, undo is one
action · **R2** several objects, or undo needs data you must capture first
(checkpoint the pre-state) · **R3** destructive, mass, or a security control —
full SR-2 gate, written rollback, independent review for multi-system plans.
Tier floors (`scripts/tier/tier-guard.js`) are a separate axis: a step can be R1
by reversibility and still sit behind the SR-2 exact-phrase gate because SR-2
lists that action (account disable, licence removal, group removal).

Aegis advises; a human administrator performs every action below.
