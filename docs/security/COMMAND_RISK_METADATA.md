# Command Risk Metadata

## What is deterministic

Claude Code 2.1.207 treats files under `.claude/commands/` as skills. The supported `disable-model-invocation: true` frontmatter field prevents Claude from selecting a command automatically; only the operator can invoke it. This release applies that supported control both to commands that directly execute privileged integrations and to every inventoried command that mixes read-only diagnostics with state-changing guidance.

Direct-integration commands also declare, in their body:

- R0–R3 risk level or range;
- read/local-write/remote-write access;
- credential sensitivity;
- operator-only invocation.

Direct-integration set (validated by `scripts/command-policy.test.js`):

- `/aegis-update`
- `/jira-create`
- `/jira-update`
- `/ps-script`

(The former Hermes/war-room direct-integration commands were removed from the
product surface in v8.6 — ADR-006; history preserves them.)

Each listed mixed-state command is operator-only and states an execution boundary: read-only diagnostics remain available, an adjacent action-specific `SAFETY GATE` may authorize only its named mutation, and explicit `PREVIEW ONLY` regions must move to a separately reviewed runbook. This is a tested documentation contract, not a claim that arbitrary prose is rendered technically unexecutable.

The repository does not claim that this metadata makes R0–R3 a complete authorization boundary. `CLAUDE.md` remains behavioral context. CLI gates, scanner tests, Claude Code permissions, and hooks enforce narrower properties.

## Why arbitrary frontmatter was not added

The installed Claude Code version does not document custom `risk`, `access`, or `credential-sensitive` command-frontmatter fields as enforcement inputs. Adding unsupported keys to all 77 commands would look machine-enforced without creating a real control. Risk metadata therefore remains explicit Markdown, while `disable-model-invocation` uses a documented field with deterministic behavior.

## Procedural command safety boundary

The mixed-state command set is an explicit audited list; adding another mixed command must update that list. Within the audited Markdown surfaces, the test discovers recognized PowerShell plus shell/native sinks in code fences, explicit portal actions, and a constrained set of imperative portal/UI patterns. It gives each discovered live code mutation exactly one same-fence owner, makes preview code inert, bounds portal ownership at the next marker/section boundary, and rejects duplicate IDs. The complete discovered set, including sink multiplicity and impact classifications, is compared exactly with `STATE_CHANGE_INVENTORY.json`; the manifest also names the independently tested Jira, memory, and security-audit client boundaries that do not live inside Markdown fences.

PowerShell gate analysis checks source order, one direct `Read-Host` assignment, and one positive case-sensitive `if ($confirmation -ceq $requiredConfirmation)` branch whose true block dominates every owned sink and whose direct `else` throws. It rejects post-read variable overwrite, dead or indirect guards, target-token omissions, and effect/confirmation mismatch. Adversarial fixtures cover missing/dead guards, variable overwrite, case-insensitive comparison, and a `-WhatIf; later-mutation` bypass. Generic `yes`, empty input, case changes, and extra whitespace do not reach the inert mocked sink; the exact source-derived phrase does.

### Google Workspace, Okta, Jamf and macOS command family (G1, v8.9)

Shell fences (`bash`, `sh`, `shell`, `zsh`, and untagged) are scanned for the administration tools of the Google/Okta/Jamf/macOS lane: `gam` (create, update, delete, undelete, suspend, unsuspend, transfer, move, add, remove, revoke, wipe, deprovision, action, and any verb not on the read-only list), `gcloud` (create, update, delete, set, IAM binding changes, enable/disable, and unlisted verbs), `curl`/`wget`/HTTPie with a write method (`-X`/`--request`/`--method` DELETE/POST/PUT/PATCH) or a request body (`--data*`, `-d`, `--json`, `--form`, upload flags), the `jamf` binary (policy, recon, manage, removeFramework, enroll, and any verb not on the read-only list), `profiles` (install, remove, renew, `-I`, `-R`), `dscl` write operations, `fdesetup` (enable, disable, add, remove, changerecovery, …), `diskutil` erase/partition/APFS delete, `softwareupdate` install, `networksetup -set…`, `systemsetup -set…`, `defaults write`/`delete`, `launchctl` load/unload/bootstrap/bootout/kickstart, and ARD `kickstart`. A command starts at the line start (also after a copied interactive prompt: `$ `, `% `, `❯ `, `user@host:~$ `, the macOS zsh default `user@host ~ % `, `[user@host ~]$ `, `bash-5.2$ `, `sh-3.2# `, a `(venv) ` prefix, `PS C:\> `, `C:\…> `, the pre-Catalina macOS bash `host:~ user$ `, the oh-my-zsh `➜  ~ `), after `;`, `|`, `&`, `{`, `(`, a backtick or `$(`, after `do`/`then`/`else`/`elif`/`if`/`while`/`until`, or after `! `. Console and shell-session transcripts (`console`, `shellsession`, `shell-session`, `sh-session`, `bash-session`, `zsh-session`, `terminal` fences) are scanned like shell fences and can carry PREVIEW ONLY markers but never a gate, so a mutation in one always fails. Wrappers that run the next word — `sudo` with any options (including `-u user`, `--user=` and a bare `--`), `doas`, `timeout <duration>`, `command`, `env` and inline `VAR=value` assignments, `nohup`, `time`, `nice`, `caffeinate`, `exec`, `script`, `xargs`, `arch -arm64`/`-x86_64` — called by name or by path (`/usr/bin/sudo`, `"/usr/bin/env"`), absolute, quoted or variable tool paths (`"$HOME/bin/gam7/gam"`), a quoted or backslash-escaped tool name (`'gam'`, `\gam`), a Windows `.exe` suffix (`gam.exe`, `curl.exe`), a name that runs into an expansion (`gam${IFS}delete`), pipelines, and `$(…)` substitution do not hide an invocation; a line ending in `\` is judged together with its continuation. In a shell fence a `#` starts a comment only where bash starts one — at the line start or after whitespace or `;`, `&`, `|`, `(`, `)`, `<`, `>` that is not backslash-escaped — and never inside a backtick substitution (where a comment ends at the closing backtick), so `true#;…`, `${#var}`, `{#;…`, `}#;…`, `echo \ #;…` and `` echo `true #`; … `` hide nothing (PowerShell fences keep PowerShell's rule, which also opens a comment after `{` or `}`). `curl --config`/`-K`, any explicit method other than GET, HEAD, OPTIONS or TRACE (`-X`/`--request`/`--method`, a method-override header, HTTPie's method word before the URL (also after an option's value, `--timeout 30 DELETE`) — `PURGE`, `MOVE`, `COPY`, `LOCK` included, in any case: `-sXpost`), a method taken from an expansion (`-X "$METHOD"`, `-X "${METHOD}"`, `--request="${METHOD}"`, `-X "$(…)"`, wget `--method="${METHOD}"`), a value glued to its short option (`-dname=value`, `-d$BODY`), and an unquoted `$…` argument count as writes, as does HTTPie `--raw`. Indirect execution is its own fail-closed sink (`indirect-exec`) that needs a gate: an interpreter one-liner (`python`/`perl`/`ruby`/`node`/`expect`/`php` with `-c`, `-e` or `--eval`), a scheduled run (`at` with a time or option, `batch` ending a command, `crontab` other than `-l`), a root shell (`sudo -s`, `-i`, `--shell`, `--login`), `ssh` with a remote command, any shell interpreter or `osascript` in command position (`| bash`, `bash <(…)`, `/bin/sh -c`), `su … -c`, `env -S`, `find … -exec`, `eval`, or a substitution or variable in command position (`$(which gam) …`, a backtick, `${GAM:-gam} …`, `"$GAM" …`, `"$@"`). Known limits: a tool name inside a quoted string handed to a program this grammar does not list (`tmux new -d '…'`, `screen`, `watch`, `parallel`), a script file run by name (`python3 script.py`, `python3 -m module`, `./fix.sh`) or code fed to an interpreter on stdin or a here-document (`python3 <<EOF`), an alias defined earlier in the same fence or in a document without a gated shell fence (`alias g=gam; g delete …`), quote-split or partly escaped spellings (`g''am`, `ga"m"`, `g\am`), a line behind a root prompt `# ` (read as a comment), macOS administration and device-state tools that are not on the list above (`dseditgroup`, `sysadminctl`, `scutil --set`, `spctl`, `pmset`, `security`, `tmutil`, `installer`, `nvram`, `chflags`, `xattr`, `shutdown`/`reboot`, `kill`/`killall`, `mdmclient`, `dsconfigad`, `createhomedir` — none of the 19 runbooks runs one in a shell fence), and code outside fences (indented blocks, inline code) are not seen; `gam print … todrive` stays read-only by the batch's own list although it writes a Sheet to the administrator's Drive; the structure lint keeps CLI out of non-shell fences in commands. Read-only forms (`gam info/print/report/show/whatis`, `gcloud … list/describe`, HTTP GET, `profiles show/list/status`, `dscl -read/-list`, `fdesetup status`, `diskutil list/info`, `softwareupdate -l`, `networksetup -get…`, `systemsetup -get…`, `defaults read`, `launchctl list/print`, `| python3 -m json.tool`, `crontab -l`, `curl -o … -w …`, `-X HEAD`/`OPTIONS`, `-XGET`) stay live diagnostics. The test pins every listed form (`G1 detector`: 191 mutation forms in five fence languages, 59 read-only forms); the shell lane's native sinks (`rm`, `mv`, `cp`, `tee`, `chmod`, `chown`, `git`, package managers, redirects) are judged behind the same wrappers (`sudo rm …`, `… | sudo tee …`, `xargs rm …`); the structure lint (`scripts/lint/command-structure.js`) applies the same wrapper, indirect and quoted-name rules, and its comment rule (a `#` after whitespace only) is stricter, so it sees at least what the detector sees.

A shell mutation is owned by a same-fence `# SAFETY GATE [id]` in an explicitly tagged `bash`/`sh`/`shell`/`zsh` fence (never untagged). The gate is checked with a plain-text grammar — no PowerShell engine is involved: the six fields (`Target`, `Effect`, `Scope`, `Reversibility`, `Required confirmation: type exactly "PHRASE"`, and the standard sentence `Failure behavior: Empty, declined, "yes", or any other response means stop, and no change is made.`); exactly one `required_confirmation="PHRASE"` literal with no expansion, equal to the field phrase; and exactly one top-level `if IFS= read -r confirmation && [ "$confirmation" = "$required_confirmation" ]; then` — the only `read` in the fence — whose true branch contains every owned sink, with a direct `else` that only prints to stderr and ends in `exit` with a status from 1 to 255 (bash takes the status modulo 256, so `exit 256` would succeed). The read sits inside the condition so the shell parses the whole `if … fi` before it reads: pasted line by line, or fed on stdin (`bash -s`), the next pasted line is compared and rejected rather than taken as the answer while the sink runs outside the gate (the standalone `read` of the earlier form did exactly that). Every comment in a gated fence sits on its own line and contains no backtick, `$`, `;`, `|`, `&`, `<`, `>`, parenthesis, backslash, apostrophe, `!` or unbalanced double quote, and no executable line carries a trailing comment: in a shell that does not treat `#` as a comment (stock interactive zsh without `interactive_comments`), each comment line is then an inert unknown command `#`, while a trailing comment would have turned the template into an env-prefixed command and let an empty answer through. Only comments may precede the marker, only the comment header may sit between the marker and the template, and only comments and plain `printf '%s\n' "…"` / `echo "…"` prompts between the template and the comparison. In a document with a gated shell fence (an operator pastes fences into one shell), no other shell fence may name `confirmation` or `required_confirmation` in any of the readings below, and no shell line — in a sibling fence or in a gated fence itself, after `fi` included — may define a function (including `[`), set an alias, `eval`, `trap`, `declare`/`readonly`, `unset`, `exec`, `source`/`.`, `builtin`/`enable`/`disable`, change shell options, or hook the prompt or a key (`PROMPT_COMMAND`, `PS0`, `precmd`/`preexec`, `bind`, `bindkey`, `zle`), or assign `BASH_ALIASES`. These statements are judged in every shell command position (line start or a copied prompt, after `;`, `&`, `|`, `(`, `)` — a case label included — `{`, `}`, `!`, a backtick, `$(`, or `do`/`then`/`else`/`elif`/`if`/`while`/`until`), behind any wrapper (`command`, `env`, `time`, `sudo`, …) or a leading backslash, on the logical line bash reads (a line ending in a backslash joined with the next one, the backslash-newline removed, so `[ (\` + `) { … }` is one function definition), and on three readings of it: as written; with ANSI-C escapes decoded (`$'\x61lias'`, `$'\141lias'`, `$'\u0061lias'`) and quotes, a locale `$"`, and backslashes removed (`'alias'`, `$"alias"`, `al\ias`, `r''eadonly`, `required_confirm""ation`); and with each brace expansion reduced to its first alternative, innermost first, the word bash runs as the command (`a{lias,}`, `re{adonly,}`, `{a{l,},}ias`). So `{ alias '['=true; }`, `if :; then readonly …; fi` or `case x in x) alias …;; esac` counts as much as a bare `alias`, and the gate-variable rule sees the same readings. A sibling fence is read both as bash reads it and with `#` as a plain word, so a comment line or trailing comment that carries `; readonly …` counts too. A command name produced by a variable or substitution in command position (`$c …`, `"$c" …`, `$(…) …`) is an ungated indirect-execution sink. Limit: the analyzer is a pattern grammar over these readings, not a shell parser — a builtin or gate-variable name produced by a quoting, escaping, expansion or parsing step these readings do not model is outside what it proves. `${confirmation…}` and `${!…}` expansion, a second `read`, direct reassignment, `printf -v`, `mapfile`/`readarray`, `getopts`, `let`, `coproc`, `wait -p`, a gate variable used as a loop variable or array, `read` without `IFS=` or `||` in the condition, `elif`, `|| true`, negated comparison, and dead or nested wrappers are rejected (72 adversarial fixtures in the test). The harness then executes the fence's own lines from its first line up to the comparison in `bash` where available (always on the Linux CI leg; the Windows leg has no bash and runs the grammar checks only), followed by the canonical comparison, one mocked line in place of the positive branch, and the fence's own else body, three ways: as a script; with every comment line's `#` quoted (`'#'`), which is how a shell that does not treat `#` as a comment sees it; and fed on stdin with a read-back line after `fi`, as a line-by-line paste arrives. As a script and with `#` quoted, the exact phrase reaches the mocked sink once and empty, `yes`, case changes, padding and a trailing backslash exit non-zero without reaching it; fed on stdin, the run stops at the gate. A smuggled overwrite, a standalone `read`, or a comment that becomes code once `#` is quoted makes the harness fail. Limits: the harness runs bash only — zsh's own parser is not executed (the `#`-as-word mode is modelled in bash), fish and PowerShell cannot run the template (fish rejects `then`, so nothing runs), and bracketed-paste behaviour of a particular terminal is not modelled. Two committed fixtures (`scripts/fixtures/command-safety-gates/`) prove a GAM fence without a marker fails and the same fence with a correct marker passes.

Portal discovery gained the lane's verbs (Suspend, Unsuspend, Reactivate, Undelete, Deprovision, Powerwash, Lock, Unlock, Erase, Enroll, Unenroll, Unmanage, Unassign, Activate, and ChromeOS's Re-enable in the lane's click grammar only) with matching confirmation families, and a case-sensitive cue for Admin console, Okta, Jamf, Apple Business (and its former name Apple Business Manager), System Settings, Self Service, Fleet, Zoom Rooms, ChromeOS and Chromebook lines: a list item carrying that cue whose breadcrumb ends in an action, or that says Click/Select/Choose/Tap an action, is a mutation candidate and needs a section-local gate or preview owner. Inside a G1 lane document (the 19 runbooks, `docs/portal-nav-google-2026.md`, `docs/gws-reversibility.md`) the same click grammar also applies to list items carrying a generic portal cue (Devices, Users, Settings…), so a control named without its product ("At the top, click **Disable selected devices**") is still a candidate, and any list item there that starts with Click/Select/Choose an action is one even with no cue at all; Microsoft runbooks keep their original grammar. Known limitation: a Google/Okta/Jamf CLI written inside a PowerShell fence is outside this grammar; the structure lint (`cli-in-shell-fence`) rejects that placement in commands.

### Fleet, Slack, Linear and the G2 Jamf Pro and Google Workspace runbooks (G2, 2026-10-27)

Shell fences gained one sink, `fleetctl` (`fleetctl-write`): `get`, `query`, `version` and `help` are reads; any other verb, a bare `fleetctl`, or a path or wrapper form (`sudo`, a quoted path, `fleetctl.exe`) is a write and needs a same-fence shell gate or a preview marker. A Slack Web API or Linear GraphQL call written with `curl` is a POST with a body, so the existing `http-write` sink already catches it; the G2 runbooks read Slack and Linear through the read-only adapters instead (`scripts/adapters/README.md`). Inside a G2 lane document (the runbooks matched by `G2_LANE_DOCUMENT` in the test) the click grammar also treats Archive, Unarchive, Export, Approve, Disconnect, Flush, Distribute, Redeploy, Uninstall, Trash, Rotate, Post, Accept, Decline and "Show ... key" as actions, applies to every list item with or without a product cue, and checks each gate's Effect against 25 more action families (archive, approve, post, run, turn off, scope, exclude, enforce, close, mark, restrict, invite and others), each with the confirmation words its phrase must contain. These additions apply to G2 documents only, so every Microsoft and G1 gate keeps its earlier reading. Fixtures for each form are in the G2 tests at the end of `scripts/command-safety-gates.test.js`.

The discovery grammar is intentionally documented rather than described as universal. Novel prose, a new language, indirect function calls, or new sink vocabulary can fall outside it. Semantic review and scanner extension remain required, and the test fails new recognized imperative/code sinks that lack a section-local gate or preview marker.

Reference modules that contain state-changing examples use a parallel boundary: their read-only diagnostics remain usable, while explicit preview regions are planning references only. The vulnerability checklist is planning-only throughout.

For every new or changed command branch:

1. Inventory any line or portal step that can change local, tenant, device, network, or third-party state.
2. Keep it unexecutable by default or add an immediately adjacent action-specific gate.
3. Use a distinct confirmation for each target and effect; one phrase never carries into a later phase.
4. Add a failing structural test and source-derived inert exact-match model before the implementation.
5. Extend the pre-commit scanner when the branch introduces a new dangerous sink.

Semantic review remains required. Frontmatter and structure tests narrow invocation and documentation behavior; they do not turn Markdown into a complete authorization system.
